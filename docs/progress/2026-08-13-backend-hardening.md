# CrossHare 后端加固 - 2026-08-13

## 目标

修复后端 review 发现的同步信任边界、上传完整性、并发落盘、进程启动、配置持久化、音频资源限制和语音服务配置问题。

## 已完成

### 媒体同步和文件安全

- 新增统一 SHA-256 与跨平台文件名校验。
- Android 推送接口现在要求有效的文件大小头，默认单文件上限 20 GiB，并在落盘前重新计算 SHA-256。
- 文件归档使用原子不可覆盖的目标占位；同日期、同文件名的并发上传会生成唯一文件名。
- 数据库插入会报告并发重复；未被数据库接受的额外落盘文件会立即清理。
- 历史 mDNS 桌面拉取路径默认关闭，仅允许通过 `CROSSHARE_LEGACY_PULL_SYNC=1` 显式开启。
- 显式开启旧版拉取后，仍会验证 hash、大小、文件名、恢复路径和下载后的真实内容。
- 修复手机 IPv6 地址构造，并为旧版大文件拉取增加两小时总超时。

### 服务生命周期和持久化

- HTTP 监听改为启动阶段同步绑定；端口冲突会让进程立即以失败退出，使 systemd 能正确报告并重启。
- `config.json` 改为同目录临时文件、`fsync`、原子 rename，保存失败会回滚内存状态。
- 认证请求的 `LastSeen` 落盘频率限制为每设备最多每分钟一次，减少配置文件写放大。
- 配对 JSON 拒绝未知字段，并限制设备标识长度。

### 音频、STT 和文本注入

- 音频上传只接受 PCM16LE 16 kHz 单声道，默认限制 64 MiB 和两分钟读取窗口。
- 录音目录与文件改为私有权限。
- 默认实时转写地址统一为 `ws://127.0.0.1:8013/v1/audio/realtime`。
- UI 就绪判定只要求直连的 `stt-realtime`，不再错误依赖可选 gateway。
- Portal 文本注入对完整文本序列加锁，避免相邻 final 结果的按键交错。
