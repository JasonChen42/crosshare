# CrossHare 照片管理重构 — 2026-09-08

## 当前交付

第一版可构建的 Android 照片客户端与 Go 内置 Web 照片库。原有服务未替换；独立预览运行在 http://127.0.0.1:8385/，数据目录为 /tmp/crosshare-photo-preview-data，包含明确命名的界面验证数据。

### Android

- 默认首页改为照片，底部为照片 / 相册 / 传输 / 语音。现有麦克风卡片独立放在语音页，设置和配对入口保留。
- 中性浅色与绿色强调色；本机、电脑、合并浏览；长按多选、原图预览与双指缩放。
- 本机目录相册、电脑逻辑相册、新建相册、加入电脑相册、远端收藏。
- 选择上传，待上传哈希持久化；开启传输后轮询电脑待接收任务。
- 下载使用私有部分文件、HTTP Range、SHA-256 校验，再通过 MediaStore IS_PENDING 发布到 Pictures/CrossHare 或 Movies/CrossHare。
- 保存 URI 记录与回执分离；回执失败重试不重复保存；已有同哈希本机文件先校验再确认。
- 暂停停止前台服务，下次开启恢复任务。处理 Android 15 前台服务超时。并非不受系统限制的永久后台服务。
- Room v1→v2 保留数据迁移：增加修改时间，媒体 ID 唯一键改为 ID + 类型，避免照片和视频 ID 冲突；扫描后清理已移除的本机索引。
- 接收 App 自有图片不强制要求完整图库权限；允许 Android 14 部分照片授权；通知权限拒绝不再阻止媒体接收。

### Go / Web

- `/` 是照片库；`/voice` 保留原语音状态页面并提供返回图库入口。
- 静态 HTML/CSS/JS 通过 go:embed 分开管理，没有新增 Node 运行时依赖。
- 电脑拖拽/选择导入，流式落盘并复用原上传校验；同哈希上传串行化，避免跨设备并发创建多份原图。
- 分页图库、文件名搜索、收藏、逻辑相册、多选发送、设备配对信息、传输记录。
- 原图接口支持 Range / ETag，缩略图支持 Go 标准图片解码器，JPEG EXIF 方向校正；缓存解码限尺寸且串行，避免高并发内存放大。
- `delivery_tasks` 持久化目标设备和状态；手机只能查看自己的任务、确认自己的保存结果。失败回执保留待接收状态，Web 每五秒更新传输页。
- 本机图库接口同时验证 loopback 连接、Host、Origin；写入要求自定义请求头。移动端仍使用配对 Bearer Token。
- 新增 `CROSSHARE_DATA_DIR` 与 `--port`，可运行隔离预览，无需更改原配置或服务。

## 主要接口

手机使用 `/api/library`，Web 使用本机专用 `/api/ui/library`：

- `GET /`（前缀自身）：分页目录，offset / q / album / favorite。
- `GET /asset/{hash}`：原图，`download=1` 提示下载。
- `GET /thumbnail/{hash}`：JPEG 预览。
- `GET /transfers`；`POST /send`：创建待接收任务。
- `POST /api/library/transfers/{id}/ack`：手机保存回执或失败原因。
- `GET/POST /albums`；`POST /albums/{id}`：相册和成员。
- `POST /favorite/{hash}`：收藏。
- `POST /api/ui/library/import`：本机浏览器导入。
- `GET /api/ui/library/devices`：不包含令牌的设备信息与配对码。

## 明确边界及后续

- 本轮完成手动双向传输和图库管理第一版。自动同步相册规则、全量增量游标、删除/回收站、跨设备元数据冲突解决尚未实现。
- 电脑目录通过 Web 显式导入；没有目录监控或自动导入整个文件系统。
- 上传失败会从整个文件重试；下载支持断点续传。持久化上传任务目前使用偏好存储，后续可迁移到统一 Room 任务表。
- 桌面沿用既有 synced_files 物理记录，增加相册/收藏/投递任务；不是已完成完整 assets/replicas 数据模型迁移。
- “已上传”“已送达”是历史记录，不是持续验证设备原图存在的保证。不会传播删除。
- WebP/HEIC/RAW、视频封面等标准解码器不支持的缩略图显示回退；原图仍可按浏览器/手机的格式支持下载或查看。Web 导入仅接受内容检测识别为 image/video 的文件。
- 语音进程的原启动策略保留，照片 API 不查询或依赖语音服务；完整的语音按需启停留待后续。
- 当前网络模型依然是可信局域网；本机 Web 没有向远端浏览器开放。
